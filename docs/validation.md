# Проверка конвертера 29.09.2026

## Автоматические проверки

16 тестов `python -m unittest -v tests.test_delta_bars` прошли. Быстрый поиск границ сопоставлен с прямым последовательным накоплением на 54 последовательностях, включая 50 случайных, при шести разных порогах. Проверены точность tick rule, нейтральные сделки, дубликаты времён, неделимые сделки и остатки дня.

Интеграционные проверки покрывают полное окно из 20 дней, исключение выходных, отсутствие текущего дня в калибровке, начальный прогрев, дозапись, отсутствие дубликатов, изменение/добавление/удаление старого архива, пустые дни, разделение настроек, запрет второго писателя, некорректный источник и откат всей дневной транзакции при ошибке SQLite.

Для MIX 03.01–28.01.2022 — 20 дней прогрева. Для RTS использованы 20 предшествующих будних дней декабря 2021 года. Сентябрьская проверка включает наблюдавшуюся ночную склейку и торги выходных дней.

Независимое последовательное чтение CSV подтвердило сохранение числа сделок и объёма в каждом из 40 дней с барами: всего 13 590 464 сделки. Во всех этих днях окно содержит 20 дат и заканчивается строго раньше даты строящихся баров. `PRAGMA integrity_check` вернул `ok`, нарушений внешних ключей нет.

Максимальный модуль относительной ошибки **на обучающем окне**: 0,7353% на проверке начала 2022 года и 0,7157% на сентябрьской проверке. Это не гарантия аналогичной ошибки на новых днях: например, RTS 14.01.2022 получил 505 баров при 197 непустых пятиминутных интервалах, поскольку текущая активность существенно отличалась от предыдущего окна. Метод не использует будущие данные для искусственного выравнивания дневного количества.

Повторный запуск на начальном участке пропустил все 43 дневных архива RTS (включая прогрев) и 23 MIX; добавлено 0 баров.

В `C:\data_quote\delta_bars.sqlite3` переносится база начального участка до 02.02.2022: **6 738 баров**. Сентябрьская проверка выполнена отдельно. Вся оставшаяся история будет дозаписываться командой `python tick_to_delta_bars.py` с тем же началом 2022-01-01.
