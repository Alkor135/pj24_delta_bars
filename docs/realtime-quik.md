# Два графика RTS и MIX в реальном времени

## Первый запуск

1. Запустите QUIK из `C:\QUIK_VTB_2025_ЕБС` и подключитесь к серверу брокера.
2. В **Сервисы → Lua-скрипты** добавьте и запустите
   `C:\QUIK_VTB_2025_ЕБС\lua\QuikSharp.lua`. Скрипт и вспомогательные файлы
   уже есть в этой папке; графики не заменяют установленные файлы QUIK.
3. В QUIK включите получение обезличенных сделок для нужных контрактов RTS
   и индекса Мосбиржи. Создайте таблицу обезличенных сделок и проверьте наличие
   сделок обоих инструментов **с начала календарного дня**. Конкретный объём
   доступной истории зависит от настроек терминала и сервера брокера.
4. Запустите **оба** файла `start_chart_realtime_RTS.cmd` и
   `start_chart_realtime_MIX.cmd`. Они открывают самостоятельные окна.

Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_RTS.py
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_MIX.py
```

Первое окно автоматически запускает скрытый общий сборщик. Второе подключается
к нему. Закрытие одного окна не останавливает другое. Через 90 секунд без
обращений графиков сборщик закрывается. Запускать два самостоятельных QuikPy
клиента на ту же пару портов не следует: установленный QuikSharp обслуживает
одну пару соединений.

Зависимости уже соответствуют обычному графику:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-chart.txt
```

Дополнительные Python-библиотеки для связи не нужны: используется рыночная
часть JSON-протокола установленного QuikSharp. Запросов выставления заявок нет.
Ответы и события читаются в UTF-8 или Windows-1251: русские поля установленного
QUIK/dkjson могут приходить в CP1251, в том числе в справочнике контрактов.

## Общая конфигурация

Оба окна используют `realtime_quik.json` в корне проекта. Значения по умолчанию:

| Поле | Значение и назначение |
| --- | --- |
| `quik_dir` | `C:\QUIK_VTB_2025_ЕБС`: расположение терминала для настройки. Терминал и Lua-скрипт запускаются пользователем. |
| `host` | `127.0.0.1`: терминал на этом компьютере. |
| `requests_port` / `callbacks_port` | `34130` / `34131`: порты установленного QuikSharp. |
| `collector_port` | `34200`: локальный HTTP общего сборщика. |
| `cache_dir` | `.live_cache` относительно JSON: отдельный журнал восстановления. |
| `request_timeout` | `15`: таймаут запроса к QUIK в секундах. |
| `reconcile_seconds` | `60`: повторная сверка доступных сделок текущего дня. |
| `idle_seconds` | `90`: завершение сборщика без обращений окон. |
| `instruments.RTS` | Класс `SPBFUT`, префикс `RI`, `sec_code=null`. |
| `instruments.MIX` | Класс `SPBFUT`, префикс `MX`, `sec_code=null`. |
| `price_scale` | `1`: множитель цены из QUIK для совместимости с исторической котировкой. |

При `sec_code=null` выбирается ближайший неистёкший фьючерс по `mat_date`
справочника QUIK. В заголовке выводится фактически выбранный код. Для явного
выбора замените null кодом контракта, например `"RIZ6"` и `"MXZ6"`.
Эти коды приведены как пример, а не постоянные настройки на будущие даты.

Контракт фиксируется для календарного дня. При перезапуске учитывается уже
записанная в журнале серия. Смена кода внутри дня с существующими сделками
отклоняется: смешивание разных контрактов изменило бы дельта-бары. Перед
сменой общей конфигурации закройте оба окна и дождитесь завершения сборщика
либо остановите его ручной экземпляр. Окна с разной конфигурацией на одном
порту сборщика не соединяются.

История Финама — непрерывная склейка. Автовыбор ближайшей серии QUIK не доказывает
совпадение правил склейки поставщика. Для сопоставимого графика проверьте
контракт, цену и единицы объёма. Используется `qty` в контрактах, не денежный `value`.

## Дневной порог и ночное обновление

Исторические `RTS_delta_bars.sqlite3` и `MIX_delta_bars.sqlite3` открываются
только для чтения. Сначала обновляйте их вашими ночными скриптами, затем
подготавливайте порог на требуемую дату:

```powershell
.\.venv\Scripts\python.exe prepare_realtime_thresholds.py --date 2026-10-05
```

Обычный запуск без `--date` готовит **завтрашнюю дату по Москве**. Если расписание
запускается после полуночи и графики будут работать в этот же день, укажите
этот день через `--date`. Скрипт сам не создаёт задания планировщика.

```powershell
# Один инструмент или нестандартная база
.\.venv\Scripts\python.exe prepare_realtime_thresholds.py --symbols RTS --date 2026-10-05
.\.venv\Scripts\python.exe prepare_realtime_thresholds.py --symbols MIX --db C:\data_quote\MIX_delta_bars.sqlite3 --date 2026-10-05

# Другой файл для двух графиков
.\.venv\Scripts\python.exe prepare_realtime_thresholds.py --date 2026-10-05 --output .live_cache\thresholds.json
```

Калибровка использует прошлые дни, их tick rule и целевое число непустых
интервалов из выбранного набора. При стандартной истории это 20 прошлых
будних дней и пятиминутные интервалы. Проверяются SHA-256 ZIP, указанных в `days`.
Текущий день не участвует. Дневной порог не меняется внутри дня.

Оставленные открытыми окна замечают изменения исторической SQLite, её WAL
и файла порогов. Они перечитывают ночную историю и заменяют вчерашние бары
из журнала официальными историческими барами. До первой сделки нового дня
порог уточняется по обновлённому обучающему окну. Если ночная подготовка
изменила численное значение уже после первой сделки, начатый день сохраняет
прежний порог, а окно просит нажать **Обновить**: текущий день пересобирается
из отдельного журнала с новым порогом. Перезапуск окон для ночного обновления
не требуется.

В `.live_cache\thresholds.json` хранятся дата, инструмент, набор и отпечаток
обучающего окна. Кэш для другой даты/набора/истории не применяется. Без кэша
график рассчитывает порог на старте по прошлым ZIP; это может занимать время.
Если архивы удалены или изменены, отображается ошибка вместо подмены порога
вчерашним значением. Доступная история сохраняется на графике.

Для сознательного ручного режима:

```powershell
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_RTS.py --threshold 100
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_MIX.py --threshold 450
```

Эти числа — примеры, а не рассчитанные текущие пороги. В окне показывается
«ручной порог»; такой режим может отличаться от ночного адаптивного расчёта.

## Параметры двух скриптов

### Дополнительные окна с Supertrend

Запуск двойным щелчком: `start_chart_realtime_supertrend_RTS.cmd` и
`start_chart_realtime_supertrend_MIX.cmd`. Python-скрипты:

```powershell
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_supertrend_RTS.py
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_supertrend_MIX.py
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_supertrend_RTS.py --atr-period 10 --multiplier 3 --refresh-ms 200
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_supertrend_MIX.py --start 2022-09-01 --preset fxi
```

Это дополнительные окна с прежними свечами, Семафором, SMA, объёмом и
длительностью. Они могут работать одновременно с обычными реал-тайм окнами;
все используют единственный общий сборщик и отдельные курсоры.

Два новых параметра: `--atr-period` (целое 1…10000, по умолчанию 10) и
`--multiplier` (0.01…1000, два десятичных знака, по умолчанию 3). Их можно
менять в окне. Флажок **Supertrend** скрывает обе линии без остановки потока.
Рост показан синей линией, снижение — красной. Последняя ступень продлена
на полбара, поэтому первый короткий отрезок после прогрева остаётся видимым.

Расчёт использует `calculate_supertrend` существующего статического графика:
ATR Уайлдера, середину `(high+low)/2`, подтягиваемые полосы и строгие пересечения
закрытием бара. История прогревается до `--start`. Незавершённая свеча
пересчитывает последнее значение по своим текущим OHLC; предыдущий ATR не
продвигается повторно на каждом тике. После достижения порога дельты
появляется следующий бар. Карточка показывает Supertrend, направление и ATR.

### Общие параметры

Скрипт RTS всегда открывает RTS, скрипт MIX — MIX. Остальные параметры одинаковы:

| Параметр | Назначение |
| --- | --- |
| `--config путь` | Общая конфигурация QUIK обоих окон. |
| `--data-dir C:\data_quote` | Папка стандартных исторических баз. |
| `--db путь` | Явная SQLite для этого инструмента. |
| `--dataset-id значение` | Явный набор вместо последнего доступного. |
| `--start YYYY-MM-DD` | Начало видимого участка; предыстория всё равно прогревает индикаторы. |
| `--threshold-file путь` | JSON ночных порогов; по умолчанию `.live_cache\thresholds.json`. |
| `--threshold число` | Явный положительный ручной порог. |
| `--refresh-ms 200` | Интервал GUI от 50 до 10000 мс; все сделки сохраняются независимо от частоты изображения. |
| `--preset nuf` / `fxi` | Стиль Семафора. |
| `--depths 5 12 34` | Три глубины; 0 отключает уровень. |
| `--deviation`, `--backstep`, `--point` | Исходные параметры Семафора. |
| `--ma-fast 3`, `--ma-slow 34` | Периоды SMA. |

```powershell
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_RTS.py --start 2026-09-01 --refresh-ms 200
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_MIX.py --preset fxi --depths 0 12 34
.\.venv\Scripts\python.exe chart_delta_bar_semafor_realtime_RTS.py --help
```

`--end` отсутствует: конец диапазона — текущий день. Флажок **Следить за
последним** сдвигает прежнюю ширину масштаба к новым барам. Отключение сохраняет
просмотр истории. Изменение параметров пересчитывает график; **Обновить** / Ctrl+R
перечитывает ночную историю и восстанавливает текущие сделки из журнала.

## Логика свечей и восстановление

Знак определяется изменением цены, как в историческом конвертере. Первая
сделка дня нейтральна, одинаковая цена наследует последнее направление.
Направление сохраняется между барами. Флаг покупки/продажи QUIK не используется.
Бар закрывается при `abs(delta) >= threshold`, сделка входит целиком, остаток
превышения не переносится. Полночь МСК сбрасывает tick rule и закрывает дневной
остаток; внутридневные перерывы бар не закрывают. Длительность измеряется
между первой и последней сделками бара, а не временем ожидания следующего тика.

Последний бар изменяется на каждой принятой сделке; изображение обновляется
пакетами. Семафор может удалять/переносить прежние метки, как исходный алгоритм.
Пересчёт использует всю доступную историю и текущие бары, без будущих данных.

Новые callbacks принимаются до загрузки снимка. Журнал устраняет повторы по
дате, классу, контракту и точному номеру. Поздняя сделка пересчитывает день.
При восстановлении связи снимок перечитывается; уже принятые перед разрывом
сделки сохраняются, включая ошибку снимка и хвост очереди перед полуночью.
Перезапуск окна восстанавливает сделки из отдельной
`.live_cache\quik_trades.sqlite3`. Дни, уже появившиеся в ночной БД, берутся
из неё и не дублируются журналом.

**Полнота дня не подтверждается автоматически.** Если QUIK или сборщик
запущены поздно и терминал не предоставляет утренние сделки, восстановить
их из отсутствующих данных нельзя. В окне показываются фактический контракт,
источник порога, связь, последняя сделка и ошибки входных данных. Тишина во
время перерыва не считается разрывом соединения.

## Диагностика

Ручной запуск общего сборщика:

```powershell
.\.venv\Scripts\python.exe realtime_quik_collector.py --config realtime_quik.json
```

Статус: `http://127.0.0.1:34200/status`. Если QUIK недоступен, проверьте подключение
к брокеру, запуск Lua и соответствие портов файлу `lua\config.json` установленного
QuikSharp. Если Lua сообщает об ошибке `socket.core`, нужна совместимая с
выбранной версией Lua библиотека сокетов; существующий мост не заменяется
автоматически. Перезапуск его соединения не удаляет локальный журнал.

Ошибка `UnicodeDecodeError` с текстом `utf-8` при работающем QuikSharp означала
неподдержанную прежде Windows-1251, а не отсутствие подключения к брокеру.
Она исправлена в общем модуле `source/quik_bridge.py` для ответов и callbacks.
После обновления Python-файлов закройте оба старых окна, дождитесь завершения
старого сборщика (90 секунд без обращений) и запустите оба `.cmd` заново.
При успешном подключении рядом с `RIZ6`/`MXZ6` либо выбранной другой серией
появляется **QUIK подключён**, затем меняется время последней принятой сделки.

Проверки без биржи:

```powershell
.\.venv\Scripts\python.exe -m unittest -v tests.test_realtime_core tests.test_realtime_data tests.test_realtime_feed tests.test_chart_realtime
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

Сетевые проверки используют собственные локальные серверы, Qt — offscreen,
история и журнал — временные файлы. Действующая рыночная подписка требует
отдельной проверки с запущенным терминалом и доступными сделками.

04.10.2026 подключение проверено на действующем терминале: `isConnected=1`,
выбраны `RIZ6` и `MXZ6`, снимки обезличенных сделок загружены без ошибок.
Без повторных запросов снимка за 28 секунд получены 10 настоящих callbacks RTS
и 1 MIX. Оба графика в отдельных Qt-процессах показали текущие бары и обновили
прежний холст при новых сделках. Подробности запуска тестов на Windows —
в [README проверок](../tests/README.md).
