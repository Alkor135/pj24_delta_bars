# Одновременные графики RTS и MIX из QUIK

Пользователь согласовал план в чате и разрешил реализацию 03.10.2026, уточнив,
что нужны два самостоятельных скрипта и два одновременно открытых графика.

## Результат

`chart_delta_bar_semafor_realtime_RTS.py` и
`chart_delta_bar_semafor_realtime_MIX.py` показывают историю SQLite и
изменяемый последний бар текущего календарного дня по сделкам QUIK.
Интерфейс сохраняет Семафор, SMA, объём, длительность и навигацию исходника.

## Архитектура

Установленный QuikSharp обслуживает одну пару соединений. Поэтому оба окна
автоматически используют один общий сборщик на localhost. Сборщик читает
JSON-протокол установленного QuikSharp напрямую: это позволяет обойтись
стандартной библиотекой Python без зависимости от версии QuikPy. Используются
только запросы рыночных данных. Сборщик хранит нормализованные сделки в отдельной
SQLite в `.live_cache`; исторические базы открываются только для чтения.

При соединении запускается приём callback, затем загружается снимок текущего
дня. Повторы устраняются по дате, классу, контракту и номеру сделки. Снимок
повторяется после разрыва и периодически для сверки. Сборщик публикует журнал
через локальный HTTP API с курсором. Оба окна читают его независимо.

По умолчанию выбирается ближайший неистёкший контракт RI для RTS и MX для MIX
по дате погашения из справочника QUIK. Явные коды задаются общим JSON-конфигом.
Контракт фиксируется на календарный день; разные серии внутри дня не смешиваются.
Гарантия совпадения с Финамом относится к алгоритму при одинаковых исходных
сделках, а не к полноте и склейке разных поставщиков.

## Расчёт

Tick rule повторяет `source.delta_core`: первая сделка нейтральна, равная цена
сохраняет направление, направление сохраняется между барами. Бар закрывается
при `abs(delta) >= threshold`, сделка входит целиком, превышение не переносится.
Порядок — время биржи и числовой номер сделки при одинаковом времени;
поздняя сделка вызывает повторный расчёт затронутого дня. Номер сделки не
преобразуется в float. Сброс направления и остатка — полночь МСК; клиринг не
закрывает бар. Последний открытый бар имеет `close_reason='live'`.

Порог фиксирован на день и соответствует калибровке прошлых тиков из выбранного
набора SQLite. `prepare_realtime_thresholds.py` подготавливает JSON для ночного
расписания; при отсутствии подходящего файла окно рассчитывает порог на старте
по прошлым ZIP. Подмена порога вчерашним значением запрещена. Явный `--threshold`
разрешён и обозначается как ручной. В выходные обучение повторяет правила
конвертера. Бары и индикаторы до текущего дня загружаются с прогревом; новый день
не дублирует записи исторической БД.

## Интерфейс и восстановление

Сбор, чтение истории, калибровка и расчёт индикаторов идут вне GUI. GUI обновляет
существующий холст раз в 200 мс при изменениях; обновления изображения могут
объединяться, сделки не отбрасываются. Семафор пересчитывается по всей доступной
истории. Флажок слежения сохраняет ширину масштаба; при отключении вид истории
не сдвигается. После перезапуска окно восстанавливается из журнала, затем
догружает доступные сделки QUIK. Полнота начального дня автоматически не
гарантируется и явно отмечается в статусе.

Сборщик прекращает работу через 90 секунд без обращений окон. Ошибка связи не
удаляет журнал или уже показанные бары. Все пути и параметры описаны по-русски
в заголовках скриптов и README соответствующих папок. Существующие несвязанные
изменения пользователя сохраняются; коммиты, публикации и изменения исторических
БД не входят в эту работу.

## Проверка

Сравнение последовательного расчёта с пакетным на одном потоке; равные цены,
переполнение порога, поздние и повторные сделки, граница дня, большой номер
сделки, восстановление журнала, неверный порог и несовместимый кэш. Транспорт
проверяется настоящим тестовым TCP-мостом, совместная работа — двумя клиентами
локального HTTP. Qt проверяется offscreen на реальных свечах и метках. Живой
рынок проверяется только при доступном QUIK; недоступность отражается в отчёте.
