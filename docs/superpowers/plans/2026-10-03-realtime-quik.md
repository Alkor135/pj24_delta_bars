# План реализации графиков QUIK RTS и MIX

> Для исполнителя: использовать `superpowers:executing-plans` и
> `superpowers:test-driven-development`. Пользователь уже согласовал план в чате
> и явно поручил начать реализацию; повторное согласование не требуется.

**Цель:** два одновременно работающих графика с общей подпиской QUIK.

**Архитектура:** общий сборщик QuikSharp, отдельный журнал сделок, два окна Qt.
**Технологии:** Python 3.13, стандартные socket/sqlite3/http.server, PyQt6,
pandas, finplot из существующего окружения.
**Спецификация:** `docs/superpowers/specs/2026-10-03-realtime-quik-design.md`.

## Общие ограничения

- Исторические БД только для чтения; журнал отдельно в `.live_cache`.
- Tick rule и калибровка совпадают с историческим конвертером.
- Оба окна используют один мост, работа GUI не блокирует приём сделок.
- Документация, функции, сообщения и README на русском языке.
- Работа в указанной пользователем папке; несвязанные изменения не изменять.

## Особое внимание при проверке

- Одновременный запуск двух окон не создаёт два подключения к QuikSharp.
- Поздние сделки и повторы после снимка не меняют объём ошибочно.
- Одинаковые времена и номера больше 2**53 не теряют порядок/уникальность.
- Новый день сбрасывает дельту, но продолжает прогрев индикаторов.
- Несовместимый порог и отсутствие истории не подменяются вчерашним порогом.
