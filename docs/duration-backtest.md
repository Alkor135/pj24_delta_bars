# Проверка стратегии длительности дельта-баров

Запуск двойным щелчком: `start_backtest.cmd`. Из терминала VS Code в папке проекта:

```powershell
.\.venv\Scripts\python.exe backtest_duration.py
.\.venv\Scripts\python.exe backtest_duration.py --symbols RTS
.\.venv\Scripts\python.exe backtest_duration.py --symbols MIX --entry-grid 1:45:1 --exit-grid 5:300:5

# ALF включён по умолчанию; α совпадает с начальной настройкой просмотрщика
.\.venv\Scripts\python.exe backtest_duration.py --symbols RTS MIX --entry-filter alf --alf-alpha 0.4

# Прежняя стратегия без фильтра ALF для сравнения
.\.venv\Scripts\python.exe backtest_duration.py --symbols RTS MIX --entry-filter none
```

По умолчанию перебираются 2511 пар: вход от 1 до 45 секунд с шагом 1, выход от 5 до 300 секунд с шагом 5; только выход > вход. Чтобы изменить шаг выхода на 1 секунду: `--exit-grid 2:300:1` (значительно больше пар). Полные команды и значения: `python backtest_duration.py --help`.

В VS Code можно открыть `backtest_duration.py` и выбрать Run Python File, предварительно указав `.venv\Scripts\python.exe` этого проекта. Зависимости устанавливаются командой `.\.venv\Scripts\python.exe -m pip install -r requirements-backtest.txt`.

## Обратное направление входов

Отдельная точка запуска — **`backtest_duration_reversed.py`** или `start_backtest_reversed.cmd`. Новый скрипт использует общую модель исполнения, чтобы правила двух вариантов не расходились.

```powershell
# Обратные входы с ALF для обоих инструментов
.\.venv\Scripts\python.exe backtest_duration_reversed.py

# Только RTS с явно заданными порогами и α
.\.venv\Scripts\python.exe backtest_duration_reversed.py --symbols RTS --entry-grid 1:45:1 --exit-grid 5:300:5 --alf-alpha 0.4

# Обратные входы без фильтра ALF
.\.venv\Scripts\python.exe backtest_duration_reversed.py --symbols MIX --entry-filter none
```

Сначала проверяются исходные условия сигнального бара: длительность, направление свечи, сторона ALF и время сессии. Затем **только сторона разрешённой сделки меняется на противоположную**:

| Завершённый сигнальный бар | Обычный вход | Обратный вход |
| --- | --- | --- |
| Быстрый растущий, close > ALF | Long | Short |
| Быстрый падающий, close < ALF | Short | Long |
| Направление и сторона ALF не совпадают, doji или close = ALF | Пропуск | Пропуск |

При `--entry-filter none` сравнение с ALF исключается из обеих стратегий. Часы торговли, одна позиция на инструмент, исполнение на следующем тике и правила выхода сохраняются. При одинаковых порогах совпадают моменты и цены входов/выходов, число сделок; валовый PnL меняет знак. Издержки продолжают вычитаться: для одной и той же сделки `net_reversed = -gross_normal - costs`. Простая смена знака чистого PnL дала бы неверный результат.

Подбор параметров проводится заново для обратной стратегии, поэтому её лучшие пары могут отличаться от пар обычного варианта. Для сопоставления фиксированной пары используйте одинаковые пороги, диапазон дат, α и издержки. Например, `--entry-grid 10:10:1 --exit-grid 100:100:1` задаёт ровно одну пару в обоих скриптах.

Папка результатов по умолчанию: **`C:\data_quote\duration_backtests_reversed\run_...`**. В `index.html` и отчётах RTS/MIX явно показано обратное направление входов. Метаданные сохраняют `position_direction`, `direction_multiplier=-1`, имя скрипта и фактические правила. Общий кэш содержит исходные события; разворот применяется после ALF в памяти, поэтому повторное использование кэша не смешивает варианты. Перестраивать SQLite с дельта-барами не требуется.

## Правила

Ниже описан обычный вариант `backtest_duration.py`; обратный вариант меняет только стороны входов по правилам выше.

- Используется один контракт и не более одной позиции. Быстрый **завершённый** бар с длительностью **строго меньше** порога входа даёт Long при **close > open и close > ALF**, Short при **close < open и close < ALF**. Сравнивается закрытие сигнального бара с ALF этого же бара. Doji и равенство close = ALF не дают вход. Быстрый падающий бар выше ALF и растущий ниже ALF пропускаются.
- `--entry-filter none` отключает только дополнительное условие ALF: остаются направление свечи и длительность, как в прежней стратегии. При `--entry-filter alf` параметр `--alf-alpha` по умолчанию равен **0,4**, допустимо `0 < α <= 1`. В просмотрщике выберите такое же α для сравнения сигналов с графиком.
- ALF вычисляется общей с просмотрщиком функцией Лагерра по закрытиям **всей доступной истории выбранного набора до конца теста**: предыдущие даты до `--start` служат прогревом. Состояние не сбрасывается между днями; учитываются и дневные неполные остатки, как на графике, но они сами не дают входов. Будущие бары не влияют на ALF уже завершённого сигнального бара. Начальное состояние равно первому доступному закрытию; отдельного периода запрета торговли при прогреве нет.
- Выход, когда очередной завершённый бар формировался **строго больше** порога выхода; его направление не важно. Пока бар не завершился, сигнала выхода по длительности нет.
- Исполнение сигнала — первая следующая сделка, то есть open следующего бара. Исходный порядок строк сохраняется, в том числе внутри одной секунды. Цены и границы баров сверяются с ZIP, SHA256 которого должен совпадать с журналом конвертера.
- Неполный остаток дня не даёт сигналов. Отсутствуют добавления, автоматические перевороты и стоп-приказы.
- Часы первой версии: сигнальный бар целиком после 10:00 МСК; вход до 18:30; оставшаяся позиция закрывается по первому реальному тику в 18:40 или позже. Параметры `--session-start`, `--entry-end`, `--close-time`. Это выбранное окно исследования, не полное расписание биржи. Бар, пересекающий внутридневной перерыв, сохраняет календарную длительность.
- Если после заданного времени дневного выхода нет тика, день исключается и отражается в покрытии. При аварийной остановке торгов это нельзя считать отсутствием торгового риска: такой день не смоделирован.
- Длительность считается по исходным целым секундам. Добавленные загрузчиком доли секунды не используются как точное время. Длительность 0 означает начало и конец внутри одной секунды, а не мгновенный бар.

## Издержки и единицы

PnL выражен в **пунктах котировки на один контракт**, без плеча и сложного процента. Он не равен рублёвой доходности счёта. Результаты RTS и MIX не суммируются. Шаг цены RTS — 10, MIX — 25; все наблюдаемые цены проверяются на соответствие этой решётке. Для иного инструмента/источника предусмотрен `--tick-size` с одним символом.

Издержки `--costs 0,2,4,8` — суммарные шаги цены **за круг**, вход и выход вместе. Опорный сценарий `--base-cost 4` используется для ранжирования. Половина затрат относится на вход и половина на выход. Это сценарии комиссии+спреда+проскальзывания, **не тариф ВТБ**. Исполнение по следующей сделке оптимистично в отношении задержки и очереди заявок; стакана в архиве нет.

## Подбор и контроль

До `--holdout-start 2026-01-01` находится период разработки. Внутри него выполняется последовательная проверка: подбор на предыдущих 12 календарных месяцах, применение выбранной пары на следующих 3 месяцах. Минимум `--min-trades 100` сделок на обучении.

Качество — средний дневной PnL / его стандартное отклонение. Это **не годовой Sharpe доходности счёта**. Для каждого узла берётся медиана качества соседних узлов 3×3; соседям с недостаточным числом сделок присваивается неприемлемое качество. Дополнительно требуются положительный PnL самой пары и положительная медиана. Если условия не выполняются, следующий квартал проводится вне рынка. Нулевой график такого теста — отказ от торговли, а не безубыточность сигналов.

Для сравнения берутся `--top 5` разных областей с лучшим рейтингом разработки; даже если они убыточны, их кривые остаются в отчёте как диагностика. Дополнительно показывается лидер **до издержек**, выбранный также исключительно на разработке. Шестая линия может быть скрыта в легенде — щёлкните её название. Разные области отбираются с расстоянием хотя бы четыре шага по одной из осей сетки. Это правило визуального разнообразия, не отдельная торговая модель.

Период начиная с 2026 года не влияет на выбор фиксированных пар. Его PnL показан отдельно с нуля. После просмотра результатов и изменения правил этот участок уже нельзя объявлять новым независимым контролем.

## Результаты

Каждый запуск создаёт новую папку `C:\data_quote\duration_backtests\run_...` с общим `index.html` и подпапками RTS/MIX:

- `report.html` — автономные интерактивные графики: PnL до/после затрат, отдельный контроль, просадки, месяцы, тепловые карты всех сценариев издержек, последовательная проверка.
- `results.sqlite3` — параметры, рейтинг, сводка, полный журнал выбранных сделок, дневной PnL, переоценка открытой позиции, покрытие и окна проверки.
- `grid_development.csv` — показатели всей сетки на периоде разработки при разных издержках.
- `trades.csv`, `daily.csv`, `summary.csv`, `coverage.csv`, `walk_forward.csv` — таблицы для дальнейшего анализа.
- `grid_daily.npz` — компактный дневной PnL до затрат и число сделок каждой пары за весь доступный период; читать `numpy.load(..., allow_pickle=False)`.
- `metadata.json` — точные настройки и сведения об исходной базе.

В отчёте явно указаны **условия входа**. `metadata.json` и таблица `metadata` в SQLite сохраняют режим фильтра и α; для ALF также сохраняются начало истории, число баров до `--start` и контрольная сумма истории закрытий. Журнал сделок содержит `entry_signal_close` и `entry_signal_alf` — закрытие и ALF сигнального бара. `entry_price` — цена исполнения на следующем тике; она может оказаться по другую сторону ALF. При отключённом фильтре `entry_signal_alf` пустой.

Переоценка открытой позиции проводится на открытиях/закрытиях баров и тике выхода по времени. Внутритиковые экстремумы между этими точками не измерены. Просадка может быть занижена относительно полной тиковoй кривой.

Повторный запуск не перезаписывает старые результаты. `.duration_cache` ускоряет подготовку: ключ учитывает бары, SHA256 архива и часы торговли; содержимое исходного ZIP сверяется даже при использовании кэша. Исходные базы открываются в режиме только чтения. Просмотрщик и конвертер остаются самостоятельными программами.

В кэше хранятся события **до применения ALF**. После их чтения фильтр всегда применяется заново, поэтому режимы `alf`/`none`, разные α и изменения истории прогрева не смешивают сигналы. Старый кэш можно использовать; удалять его для включения ALF не нужно. Для сопоставления двух стратегий сохраняйте одинаковые даты, набор баров, сетку порогов и издержки.
