# Проверка объёма и трендовости

Скрипты выполняют утверждённый план из
`docs/superpowers/plans/2026-10-05-volume-trend-hypothesis.md`.
Исходные ZIP/SQLite только читаются; выходные исключаются из 20-дневной базы.
Границы окна — максимальное время первой сделки и минимальное время последней
сделки среди исследуемого дня и 20 прошлых будних дат. Клиринги не вычитаются,
обе границы включаются. Все исторические объёмы пересчитываются в этом окне.

## Запуск из корня проекта

```powershell
.\.venv\Scripts\python.exe -m research.volume_trend --stage audit
.\.venv\Scripts\python.exe -m research.volume_trend --stage analyze
.\.venv\Scripts\python.exe -m research.volume_trend --stage report
.\.venv\Scripts\python.exe -m unittest -v tests.test_volume_trend
```

`volume_trend.py` управляет этапами; `volume_trend_data.py` читает исходники,
сверяет объёмы и формирует окна; `volume_trend_metrics.py` рассчитывает
индикаторы, число событий и статистические сравнения.
По умолчанию источник — `C:\data_quote`, инструменты — RTS/MIX,
период — 01.01.2022–02.10.2026, результат — `results/volume_trend`.
Параметры `--data-dir`, `--output`, `--start`, `--end`, `--symbols`,
`--repetitions` позволяют задать пути, диапазон и число bootstrap-повторов.

## Логика этапов и результаты

`audit` проверяет SHA256 каждого ZIP, сумму объёма, число тиков и последовательное
покрытие строк баров. Согласованные снимки БД и точные массивы тиков сохраняются
в `cache`. Первая/последняя сделки не гарантируют независимую полноту архива.
Список календарных будних дат без архива сохраняется отдельно; их нельзя
автоматически объявлять ошибкой или биржевым праздником.

До индикаторов фиксируется `config.json`. Контрольное окно выбирается по
95%-квантилю первых и 5%-квантилю последних сделок, округлённых внутрь до пяти
минут; берётся общее окно RTS/MIX. Повреждённая дата остаётся в исторической
очереди и блокирует сравнения следующих 20 дат.

`analyze` использует сохранённую конфигурацию аудита. Рассчитываются SuperTrend
ATR 10/3 и SMA 3/34 на дельта-барах и временных свечах 1/5/15 минут. Прогрев —
100 предыдущих баров; выходные исключаются, ночные переходы не считаются.
После подтверждённой ошибки или разрыва более 10 календарных дней прогрев
повторяется. Пригодный бар целиком лежит в общем окне, клиринговая пауза
его не исключает. Равенства SMA сохраняют последнее ненулевое направление.
Дни без пригодных переходов получают пропуск, а не нулевое число событий.

Сравниваются дни с относительным объёмом строго >1 и ≤1. Основные восемь
сравнений 2026 года получают поправку Holm; 2022–2025 — предыдущий период.
Bootstrap: 5000 повторов, блок 20 дат, проверки 40/60, seed 20261005.
Если все сегменты не длиннее блока, ДИ/p не оцениваются; короткие сегменты
при наличии длинного остаются фиксированными, их неопределённость не учтена.
Поправка Holm сохраняет размер семьи даже для отсутствующих p-значений.
Контрольные показатели: события на час/100 переходов, эффективность пути,
фиксированное окно, дневные остатки, выходные в прогреве и календарные фильтры.

`volume_trend_report.py` создаёт `report.md` и три автономных графика Plotly HTML
по сохранённым таблицам. Основные файлы: `audit.csv`, `missing_weekdays.csv`,
`daily.csv`, `comparisons.csv`, `year_and_bounds.csv`, `ratio_bins.csv`,
`sensitivities.csv`, `config.json`, `analysis_run.json`.

Пример с явными параметрами:

```powershell
.\.venv\Scripts\python.exe -m research.volume_trend --stage all --data-dir C:\data_quote --output results\volume_trend --start 2022-01-01 --end 2026-10-02 --symbols RTS MIX --repetitions 5000
```

Нужны существующие NumPy, Pandas и Plotly из `requirements-backtest.txt`.
Повреждённые ZIP дают явную ошибку качества данных и отмечаются в аудите.
Отчёт отличает недостаток статистических данных от отсутствия подтверждения связи.
Результат относится к завершившемуся дню и не проверяет прогноз по утреннему объёму.

## Отдельный интерактивный отчёт по пятиминутным барам

`volume_trend_5m_report.py` читает проверенную `daily.csv` и создаёт один
автономный HTML с интерактивными Plotly-графиками, таблицами и выводами.
Библиотека, данные и оформление встроены; интернет и сервер не нужны.

```powershell
.\.venv\Scripts\python.exe -m research.volume_trend_5m_report --source results\volume_trend --repetitions 5000
.\.venv\Scripts\python.exe -m research.volume_trend_5m_report --html results\volume_trend\five_minute_report.html
.\.venv\Scripts\python.exe -m unittest -v tests.test_volume_trend_5m_report
```

Параметры: `--source` — папка предыдущего исследования; `--html` — итоговый
файл; `--repetitions` — число повторов, по умолчанию 5000, минимум 100.
Основная семья: 16 сравнений 2026 — оба инструмента, оба индикатора, обе базы
объёма и оба окна. Поправка Holm общая для этой семьи. Проверки блоков 40/60
служат устойчивости. Исторический и полный периоды имеют отдельные семьи по
16 и не считаются независимыми подтверждениями.

ДИ симметричные по 95%-квантилю абсолютной центрированной bootstrap-ошибки,
согласованной с двусторонним p-тестом; в предыдущем отчёте были процентильные
ДИ. Интервалы индивидуальные, значимость определяется по p Holm <0,05.
Частичная поддержка, отсутствие подтверждения и обратная связь различаются.
Все абзацы с выводами рассчитываются из статистики; отсутствие значимости и
смешанные направления связи не сохраняют утверждения о поддержке из прошлого запуска.
2026 уже изучался: новый отчёт не является проверкой на ранее невиденной выборке.

Результаты: `five_minute_report.html`, `five_minute_statistics.csv`,
`five_minute_report_manifest.json`. Дополнительные пакеты не требуются.
