# Адаптивные дельта-бары RTS и MIX

Конвертер читает дневные тиковые ZIP Финама и сохраняет бары в SQLite. Работает на Python 3.10+ без установки сторонних библиотек.

## Структура проекта

В корне находятся Python-скрипты для запуска из VS Code или PowerShell:

| Скрипт | Назначение |
| --- | --- |
| `tick_to_delta_bars.py` | Конвертация тиков в адаптивные дельта-бары SQLite. |
| `check_date_db_delta_bars.py` | Вывод трёх последних различных дат баров для каждой базы в папке. |
| `chart_delta_bars.py` | Просмотр свечей, индикаторов, объёма и длительности. |
| `chart_delta_bars_supertrend.py` | Отдельный просмотрщик дельта-баров с Supertrend и настройками ATR. |
| `chart_delta_bar_semafor.py` | Отдельный график с «Семафором» MT4 5/12/34 и островами SMA 3/34. |
| `chart_delta_bar_semafor_simulate.py` | Потоковое воспроизведение реальных баров с Семафором/SMA и изменяемой скоростью. |
| `backtest_duration.py` | Проверка стратегии по длительности баров и построение отчётов PnL. |
| `backtest_duration_reversed.py` | Та же проверка с противоположным направлением каждой разрешённой сделки. |
| `backtest_stochastic.py` | Фиксированная проверка Stochastic (14, 3, 3) с ALF, тиковыми стопами и целью 2R; сравнение с ALF без стохастика. |
| `backtest_heikin_ashi.py` | Проверка только цвета Heikin Ashi с подтверждением одной/двумя свечами и исполнением по исходным тикам. |
| `patch_finplot.py` | Однократное исправление совместимости установленного finplot с русской локалью; также вызывается из `start_chart.cmd`. |

## График с «Семафором» и островами

`chart_delta_bar_semafor.py` использует свечи и интерфейс `chart_delta_bars.py`,
добавляя в область цены три независимых ZigZag «Семафора» и зелёные/красные
острова между простыми MA(close) 3 и 34. ALF и StopVolume не рассчитываются.
Сохранены объём, необязательная длительность, границы дней, неполные бары,
карточка свечи, выбор SQLite/набора/инструмента, диапазон дат и Ctrl+R.

```powershell
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py --symbol MIX
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py --db C:\data_quote\delta_bars.sqlite3
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py --preset fxi --depths 0 12 34
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py --depths 5 12 34 --deviation 1 --backstep 1
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py --ma-fast 3 --ma-slow 34 --point 1
.\.venv\Scripts\python.exe chart_delta_bar_semafor.py --start 2026-09-01 --end 2026-09-30
.\.venv\Scripts\python.exe -m unittest -v tests.test_chart_semafor
```

Параметры: `--symbol RTS|MIX`, `--data-dir` (по умолчанию `C:\data_quote`),
`--db`, `--start`/`--end` (включительные даты; по умолчанию последние 30 дней
до последнего дня базы), `--depths МАЛ СРЕД СТАРШ` (0…10000, по умолчанию
5/12/34), `--preset nuf|fxi`, `--deviation`/`--backstep` (0…10000), `--point`
(0.01…100000, два знака после запятой), `--ma-fast`/`--ma-slow` (1…10000).
Периоды, допуск, пресет, единица цены и видимость доступны в окне.

`--preset nuf` по умолчанию соответствует найденному во вложениях форума
`NUF FXi 3 Semafor-1.mq4`: Deviation=1, Backstep=1, красные верхние и зелёные
нижние метки, крупные «солнышки». `--preset fxi` соответствует
`FXi 3 Semafor.mq4` из «Островов»: Deviation=5, Backstep=3, средний уровень
жёлтый. На скриншоте «СФ 34/12/5» числа — это три глубины, а не одна тройка
Depth/Deviation/Backstep. В первой инструкции «Островов» малые точки отключены
параметром Period1=0: для этого служит `--depths 0 12 34`.

Перенесён алгоритм CountZZ: экстремумы прошлого окна Depth, фильтр допуска,
удаление слабых близких точек Backstep и финальное удаление лишних однотипных
вершин/впадин. Deviation*Point — допуск текущей цены к экстремуму окна,
а не процент разворота. Point по умолчанию равен одному пункту котировки;
для допуска в биржевых тиках задайте 10 для RTS, 25 для MIX. Размер символа
фиксирован в пикселях; «Отступ» лишь отодвигает рисунок и не меняет цену СФ.
При приближении вертикальный автомасштаб включает SMA и цены отодвинутых меток;
по краям оставляется место для крупных символов.

Предыстория до `--start` используется для прогрева, бары после `--end` не
читаются. Неполные дневные бары включены; переход дня не сбрасывает расчёт.
**Последние точки могут перемещаться или исчезать после обновления истории,
как в MT4.** Исторические метки не являются сигналами, известными заранее.
База открывается только для чтения; метки и MA в SQLite не записываются.

Источники: локальные заметки «Острова», «Острова плюс», «С форума» и их `.mq4`/
`.tpl`/скриншоты; [публикация автора 3_Level_ZZ_Semafor для MT4](https://www.mql5.com/en/code/7730),
[пояснение автора о перемещении последнего семафора](https://www.mql5.com/en/forum/178414).
У оригинального 3_Level_ZZ_Semafor из CodeBase другие стандартные периоды
5/13/34 и Dev_Step; здесь использованы именно версии и настройки ваших заметок.

## Симуляция потока баров с «Семафором»

`chart_delta_bar_semafor_simulate.py` показывает тот же график Семафора и
островов SMA, постепенно добавляя реальные бары из выбранной SQLite. База
читается один раз как снимок. По умолчанию сначала видны 200 баров выбранного
периода, затем добавляется один бар каждую секунду. В коротком диапазоне
последний бар оставляется для следующего шага; единственный показывается сразу.
После последнего бара воспроизведение останавливается.

```powershell
.\.venv\Scripts\python.exe chart_delta_bar_semafor_simulate.py
.\.venv\Scripts\python.exe chart_delta_bar_semafor_simulate.py --symbol MIX
.\.venv\Scripts\python.exe chart_delta_bar_semafor_simulate.py --interval 0.1 --initial-bars 50
.\.venv\Scripts\python.exe chart_delta_bar_semafor_simulate.py --db C:\data_quote\delta_bars.sqlite3 --start 2026-09-01 --end 2026-09-30
.\.venv\Scripts\python.exe chart_delta_bar_semafor_simulate.py --preset fxi --depths 0 12 34
.\.venv\Scripts\python.exe -m unittest -v tests.test_chart_semafor_simulate
```

Сохраняются параметры исходного скрипта: `--symbol`, `--data-dir`, `--db`,
`--start`/`--end`, `--preset`, `--depths`, `--deviation`, `--backstep`, `--point`,
`--ma-fast`/`--ma-slow`. Дополнительно: `--initial-bars` — стартовое число баров
(1…1000000, по умолчанию 200); `--interval` — секунды на один новый бар
(0.05…60, не более двух знаков после запятой, по умолчанию 1).
Зависимости те же: `python -m pip install -r requirements-chart.txt`.

В окне поле **«Интервал»** меняет скорость сразу, сохраняя позицию:
0.05 с/бар — до 20 баров/с, 0.1 — до 10, 1 — один бар/с, 5 — один бар за 5 с.
**«Пауза»/«Продолжить»** останавливает и возобновляет поток; **«Один бар»**
добавляет ровно один бар и оставляет паузу; **«Сначала»** начинает новый снимок.
**«Начальных баров»** применяется при следующем запуске. Изменение источника,
дат, набора или параметров индикаторов также начинает воспроизведение заново.
**«Следить за последним»** перемещает график с сохранением текущего масштаба;
отключите флажок для просмотра истории. Видимость и отступ меток доступны.

Индикаторы пересчитываются только по уже поступившим барам и предыстории до
начальной даты. Будущие бары снимка не влияют на Семафор/SMA. Последние метки
могут перемещаться или исчезать при каждом новом баре; старые точки тоже
обновляются на существующем холсте через API finplot. Время МСК, OHLC, объём,
дельта и реальная длительность берутся из базы; тики внутри бара не моделируются.
База не изменяется. Чтение и пересчёт идут в потоке Qt. На длинной истории
пересчёт может занимать больше заданного интервала: бары не пропускаются,
но фактическая скорость ограничена временем расчёта и обновления графика.
Таймер сохраняет заданный ритм независимо от длительности предыдущего расчёта;
новый шаг начинается только тогда, когда предыдущий уже завершён.

## Тест Heikin Ashi без других индикаторов

`backtest_heikin_ashi.py` рассчитывает Heikin Ashi из OHLC полных дельта-баров.
HA-close = (O+H+L+C)/4; HA-open = (предыдущие HA-open+HA-close)/2, а первый
HA-open = (O+C)/2. HA-high/low включают исходный экстремум и синтетические
открытие/закрытие. Неполные остатки пропускаются; рекурсия продолжается через
дни и использует всю доступную прошлую историю, включая вечерние/ночные бары.
Ни ALF, ни стохастик, ни другие индикаторы не рассчитываются. Из существующего
тестера переиспользованы только проверка исходных данных и подсчёт статистики.

Два фиксированных варианта требуют одну либо две полные свечи одного цвета
подряд: зелёные дают покупку, красные — продажу. Доджи (HA-close = HA-open)
не меняет позицию, но сбрасывает серию подтверждения. Серия также сбрасывается
на новой дате или недопустимом баре. Торговое подтверждение использует только
бары, начатые с 10:00 и закрытые до 18:40 МСК. Вход — следующий исходный тик
после закрытия подтверждающего бара; первая подходящая серия дня тоже даёт
вход. Повторный цвет удерживает одну позицию, противоположный — переворачивает.
Выход и новый вход при перевороте имеют одну реальную цену и отдельные затраты.
Цены Heikin Ashi используются исключительно для сигнала, без исполнения по ним.

Вход разрешён, если фактический тик раньше 18:30. После этого противоположное
подтверждение только закрывает позицию. Принудительное закрытие — первый тик
с 18:40; оно имеет приоритет перед цветовым сигналом. Стопов и целей нет,
позиция не переносится на другой день. Дни без исполнимого закрытия исключены
и перечислены вместе с днями прогрева в `coverage.csv`; их риск не рассчитан.
База и ZIP открываются только для чтения. Проверяются SHA256 архивов, число
строк/баров, полное покрытие, даты, порядок, исходные OHLC и решётка шага цены.
При позднем `--start` сверяются также все готовые архивы более ранней истории,
используемой в рекурсивном прогреве HA. Это увеличивает время короткого теста,
но запрещает незаметное использование повреждённого прогрева. Такие дни имеют
статус `validated_warmup` в покрытии и не входят в сделки/статистику периода.

```powershell
.\.venv\Scripts\python.exe backtest_heikin_ashi.py
.\.venv\Scripts\python.exe backtest_heikin_ashi.py --symbols RTS --start 2026-09-01 --end 2026-09-30
.\.venv\Scripts\python.exe backtest_heikin_ashi.py --confirmations 1,2 --costs 0,2,4,8 --base-cost 4
.\.venv\Scripts\python.exe -m unittest -v tests.test_backtest_heikin_ashi
```

Параметры: `--db` (по умолчанию `C:\data_quote\delta_bars.sqlite3`),
`--symbols RTS MIX`, `--start`, `--end` (обе даты включительно), `--dataset-id`
(обязателен при нескольких наборах), `--confirmations` (положительные целые
через запятую, по умолчанию `1,2`), `--costs` (шаги за круг, `0,2,4,8`),
`--base-cost` (затраты для журнала/графиков, `4`), `--output`
(по умолчанию `results/heikin_ashi`). Зависимости — `requirements-backtest.txt`.

Каждый запуск создаёт отдельную папку с автономным `report.html`, `summary.csv`,
`daily.csv`, `trades.csv`, `coverage.csv`, `metadata.json`. Результат — пункты
на один контракт, шаг RTS 10, MIX 25; половина платы за круг списывается на
входе, половина на выходе. Просадка учитывает все исходные тики открытой позиции.
Графики показывают историю и отдельно календарный 2026 год, сводка — 2022–2025
и каждый год начиная с 2026 отдельно. 2026 уже просматривался и не является
новым независимым контролем. Подбора лучших подтверждений/затрат нет; сценарии
затрат не заменяют тариф брокера, стакан и проверку реального исполнения.

## Фиксированный тест стохастика

`backtest_stochastic.py` читает `C:\data_quote\delta_bars.sqlite3` и исходные
тиковые ZIP из журнала базы. Нужны зависимости `requirements-backtest.txt`.
Рассчитывает Stochastic (14, 3, 3) и ALF с α=0,4 без подбора параметров.
Стохастик использует только полные бары, ALF также учитывает дневные остатки,
как просмотрщик. История до `--start` служит прогревом; будущие бары не используются.

Покупка разрешена при пересечении %K уровня 20 вверх, %K > %D, росте ALF и
close > ALF. Продажа зеркальна: пересечение 80 вниз, %K < %D, падение ALF и
close < ALF. База сравнения сохраняет все остальные условия и снимает только
условие стохастика. Одна позиция и один контракт; входы во время позиции и на
тике её закрытия пропускаются. Сигнал, сформированный на тике закрытия позиции,
может исполниться следующим тиком. Вход исполняется строго до
18:30 МСК, после трёх полных баров, целиком начавшихся с 10:00 одного дня.

Стоп фиксируется за минимумом/максимумом последних трёх полных баров, включая
сигнальный, с запасом один шаг. Если фактическая цена входа уже за стопом,
сделка пропускается. Цель по умолчанию — 2R от фактического входа. Стоп и цель
работают как рыночные сигналы: первое касание последней ценой инициирует выход
на следующем тике по доступной цене. Оставшаяся позиция закрывается первым
реальным тиком в 18:40 или позже. Дни без такого тика исключаются и перечисляются
в покрытии; это не моделирует риск аварийной остановки торгов. С тиками сверяются
OHLC, времена границ, число баров и полное покрытие исходных строк дня.
Известные дни прогрева построения баров также перечисляются в покрытии.

```powershell
.\.venv\Scripts\python.exe backtest_stochastic.py
.\.venv\Scripts\python.exe backtest_stochastic.py --symbols RTS --start 2026-09-01 --end 2026-09-30
.\.venv\Scripts\python.exe backtest_stochastic.py --symbols RTS MIX --costs 0,2,4,8 --base-cost 4 --reward-risk 2
.\.venv\Scripts\python.exe -m unittest -v tests.test_backtest_stochastic
```

Параметры: `--db` — база; `--symbols` — RTS/MIX; `--start` и `--end` —
включительные даты (по умолчанию от 2022-01-01 до конца доступной истории);
`--dataset-id` — набор баров; `--period`, `--smooth-k`, `--smooth-d` — окна
стохастика; `--alf-alpha` — α ALF; `--reward-risk` — цель в исходных рисках;
`--costs` — сценарии затрат за круг через запятую; `--base-cost` — сценарий
графиков и журнала сделок; `--output` — каталог результатов, по умолчанию
`results/stochastic`. Шаг RTS — 10, MIX — 25. Издержки не являются тарифом брокера.

Каждый запуск создаёт отдельную папку `run_...`: автономный интерактивный
`report.html`, `summary.csv`, `daily.csv`, `trades.csv` при опорных затратах,
`coverage.csv` и `metadata.json` с настройками и контрольными суммами.
Результат — пункты одного контракта, не рублёвая доходность; RTS и MIX не суммируются.
Просадка учитывает каждый исходный тик открытой позиции и обе половины затрат.
Периоды 2022–2025 и 2026 показываются отдельно. Поскольку 2026 год уже
просматривался в предыдущем анализе, он не объявляется новым независимым контролем.
При появлении данных за последующие годы каждый год получает отдельные строки
сводки; график 2026 года ограничен его календарными границами.

Откройте в VS Code папку `C:\Users\Alkor\VSCode\pj24_delta_bars`. В команде **Python: Select Interpreter** выберите `.venv\Scripts\python.exe` этого проекта, откройте нужный корневой скрипт и нажмите **Run Python File**. Параметры командной строки удобнее передавать в терминале.

Из терминала PowerShell в папке проекта:


## Правила построения

Для каждой сделки определяется знак по tick rule:

- цена выросла относительно предыдущей сделки этого дня: `+volume`;
- цена снизилась: `-volume`;
- цена не изменилась: используется последнее ненулевое направление;
- до первого изменения цены объём считается нейтральным, дельта равна нулю.

Это оценка направления по цене; достоверных признаков инициатора сделки в исходных CSV нет. Поэтому столбцы называются `up_volume` и `down_volume`, а не объёмом рыночных покупок/продаж.

Бар закрывается на первой сделке, после которой `abs(sum(signed_volume)) >= threshold`. Сделка входит целиком; превышение порога не переносится в следующий бар. Каждая сделка относится ровно к одному бару.

**Граница дня — календарная полночь по Москве.** Остаток сохраняется с `is_complete=0`, `close_reason='day_end'`. В новом дне направление и предыдущая цена сбрасываются. Внутридневные перерывы не закрывают бар. Ночной разрыв или смена серии на границе дневных ZIP не создаёт искусственную направленную дельту. Источник содержит непрерывную склейку, отдельный код контракта отсутствует; внутридневную смену серии по этим столбцам определить нельзя.

## Как выбирается адаптивный порог

Для дня D выбираются последние 20 доступных дат строго до D, содержащих сделки, кроме субботы и воскресенья. Праздник без тиков не входит в окно; будний праздник с тиками входит. Использование доступных дней не позволяет отличить биржевой выходной от недостающего архива: полнота исходной истории остаётся существенной для результата.

Каждый обучающий день делится на интервалы `[00:00,00:05)`, `[00:05,00:10)` и т. д. Считаются только интервалы хотя бы с одним тиком. Обеденные, вечерние и ночные пустые интервалы не добавляются к цели. Цель окна — сумма этих количеств за 20 дней.

Для нескольких целых порогов реально строятся границы дельта-баров на всех 20 днях. Считаются **полные бары и дневные остатки**, как в итоговой таблице. Выбирается проверенный порог с наименьшей абсолютной ошибкой относительно цели; при равной ошибке выбирается меньший порог. Порог фиксируется на весь день D.

Алгоритм использует сужение диапазона и проверку соседних кандидатов. Число баров не обязано быть строго монотонной функцией порога из-за неделимых сделок и взаимного погашения дельты. Поэтому подбор приближённый; глобальный оптимум и точное совпадение числа баров не обещаются. Порог, полученное число баров и ошибка калибровки сохраняются в таблице `days`.

**Данные D и будущих дней не участвуют в выборе порога D.** Сходство с количеством пятиминуток обеспечивается на прошлом окне. В текущем дне число баров может существенно отличаться при изменении активности и структуры потока сделок.

До накопления 20 дней сохраняется только статистика прогрева. Если есть архивы до `--start`, используются последние 20 непустых будних дней из них. Поэтому RTS может иметь бары сразу с начала 2022 года, а MIX, доступный с января 2022 года, сначала проходит прогрев. Дни субботы/воскресенья с тиками получают бары при наличии полного окна, но не добавляются в обучающую историю. Для выходных нельзя ожидать той же точности числа баров, что для будней.

## SQLite и дозапись

Таблицы:

- `datasets`: параметры расчёта и версия алгоритма в JSON.
- `days`: исходный ZIP, SHA-256, число сделок и объём, статус дня, порог, границы обучающего окна, цель и результат калибровки, число сохранённых баров. Это также журнал прогресса.
- `bars`: собственно бары. Ключ — `(dataset_id, symbol, day, bar_index)`.

`bars` содержит `start_time`, `end_time`, OHLC, `volume`, `delta`, `up_volume`, `down_volume`, `neutral_volume`, `tick_count`, `threshold`, `is_complete`, `close_reason`, `start_row`, `end_row`. `bar_index` начинается с нуля внутри дня; номера строк тиков начинаются с единицы без заголовка.

Время записано текстом `YYYY-MM-DD HH:MM:SS.fffffffff`, московское UTC+03:00. Девять знаков сохраняют искусственные доли секунды из архива, но не обозначают реальную точность времени биржевых сделок. Метка времени не является уникальным ключом. Цены RTS/MIX хранятся как `REAL`, объёмы, дельта и порог — как `INTEGER`.

День и его бары записываются одной транзакцией. Поэтому неполный день не может быть помечен как обработанный. Незавершённый бар не переносится через календарную границу: отдельного промежуточного состояния внутри дневного ZIP для возобновления не требуется. Повторное чтение последних 20 дней восстанавливает обучающее окно.

При каждом запуске SHA-256 выявляет изменение старого архива. Добавление файла задним числом или удаление ранее обработанного файла также обнаруживается. Производные дни и бары начиная с первой затронутой даты удаляются **только для текущего набора и инструмента**, затем пересчитываются до `--end`. Если `--end` раньше уже рассчитанного конца, затронутые последующие результаты останутся удалёнными до следующего запуска с более поздним `--end`.

Параметры `--start`, `--lookback`, `--target-minutes`, путь источников и версия алгоритма определяют `dataset_id`. При их изменении создаётся отдельный набор, чтобы разные правила не смешивались. `--end`, `--symbols` и путь базы в идентификатор не входят. Для обычной дозаписи сохраняйте исходное значение `--start`.

Рядом с базой возможны служебные файлы `-wal`, `-shm`, `.lock`. Не удаляйте их во время работы. `.lock` может оставаться после завершения — системная блокировка автоматически снимается. Одновременный второй конвертер той же базы будет остановлен.

## График дельта-баров с Supertrend

`chart_delta_bars_supertrend.py` использует окно и свечи исходного просмотрщика,
добавляя толстую синюю линию Supertrend при росте и красную при снижении.
Последняя ступень доходит до правого края свечи, даже если новая ветвь
появилась только на последнем баре.
Ветви Supertrend рисуются без прореживания точек, чтобы масштабирование
сохраняло короткие развороты и разрывы между направлениями.
Индикатор включён по умолчанию; ALF и Volume Stops первоначально скрыты,

Флажок **Длительность** включает ту же столбчатую панель в минутах,
что и в `chart_delta_bars.py`; отрисовка наследуется из общего `ChartCanvas`.
Зависимости те же: `requirements-chart.txt`.

```powershell

.\.venv\Scripts\python.exe chart_delta_bars_supertrend.py --symbol MIX

.\.venv\Scripts\python.exe chart_delta_bars_supertrend.py --symbol RTS --start 2026-09-01 --end 2026-09-28
.\.venv\Scripts\python.exe chart_delta_bars_supertrend.py --db "C:\data_quote\delta_bars.sqlite3"
.\.venv\Scripts\python.exe chart_delta_bars_supertrend.py --help
```

| Параметр | Назначение |
| --- | --- |
| `--symbol RTS` / `--symbol MIX` | Инструмент при открытии окна; по умолчанию RTS. |
| `--data-dir C:\data_quote` | Папка отдельных баз RTS/MIX; это значение по умолчанию. |

| `--atr-period 10` | Период ATR в дельта-барах, целое число 1…10000; по умолчанию 10. |
| `--multiplier 3` | Множитель ATR, 0.01…1000 с двумя десятичными знаками; по умолчанию 3. |

Период и множитель можно менять в окне: окончание редактирования запускает
фоновый пересчёт. Флажок Supertrend скрывает/показывает обе ветви без чтения базы.
Настройки 10/3 выбраны как начальные: по скриншоту точные параметры не определить.

True Range равен максимуму `high-low`, `abs(high-prev_close)` и
`abs(low-prev_close)`; на первом баре используется `high-low`. Первый ATR —
среднее первых N значений True Range, далее применяется сглаживание Уайлдера:
`ATR = prev_ATR + (TR - prev_ATR) / N`. Начальные полосы —
`(high+low)/2 ± multiplier*ATR`. Полосы подтягиваются по предыдущему закрытию,
а тренд переключается только при строгом пересечении текущей полосы ценой
закрытия. [Описание формул Supertrend](https://www.tradingview.com/support/solutions/43000634738-supertrend/).

До накопления N баров Supertrend отсутствует; на первом рассчитанном баре
выбирается нисходящая ветвь. При короткой истории свечи отображаются,
а строка состояния сообщает о прогреве. Расчёт использует всю предысторию
выбранного набора до `--end`, затем ограничивает видимый диапазон: изменение
`--start` не меняет значения на общих барах. Будущие бары не используются.
Неполные дневные бары включены в ATR и Supertrend; на границе дня состояние
сохраняется, ценовой разрыв учитывается через предыдущий close.
В карточке под курсором отображаются Supertrend, направление и ATR.
SQLite открывается только для чтения; индикаторы в базу не записываются.

## Проверка стратегии длительности

Запуск: `start_backtest.cmd` или `.\.venv\Scripts\python.exe backtest_duration.py`.

По умолчанию RTS и MIX проверяются отдельно: вход — длительность завершённого бара меньше порога 1…45 секунд с шагом 1; выход — больше порога 5…300 секунд с шагом 5. Проверяются пары с порогом выхода больше порога входа. Сравниваются сценарии издержек 0, 2, 4 и 8 шагов цены за круг.

**Фильтр ALF включён по умолчанию:** покупка требует растущего сигнального бара с `close > ALF`, продажа — падающего с `close < ALF`. При равенстве входа нет. ALF и его прогрев совпадают с просмотрщиком при одинаковом α (по умолчанию 0,4). Сделка исполняется на следующем тике; выход по длительности сохраняется.

```powershell
# Новый вариант: длительность + направление бара + сторона ALF
.\.venv\Scripts\python.exe backtest_duration.py --symbols RTS MIX --entry-filter alf --alf-alpha 0.4

# Прежний вариант для сравнения
.\.venv\Scripts\python.exe backtest_duration.py --symbols RTS MIX --entry-filter none
```

Условия входа и α записываются в отчёт, а close и ALF сигнального бара — в журнал сделок. Кэш исходных событий общий; фильтр применяется заново при каждом запуске.

Для обратных входов используйте отдельный скрипт или `start_backtest_reversed.cmd`:

```powershell
.\.venv\Scripts\python.exe backtest_duration_reversed.py
.\.venv\Scripts\python.exe backtest_duration_reversed.py --symbols RTS
.\.venv\Scripts\python.exe backtest_duration_reversed.py --symbols MIX --entry-filter none
```

В обратном варианте разрешённый сигнал покупки открывает продажу, а сигнал продажи — покупку. При включённом ALF это **Short после быстрого растущего бара выше ALF**, **Long после быстрого падающего бара ниже ALF**. Отбор по ALF выполняется до разворота. Длительность, исполнение на следующем тике, выходы и ограничение одной позиции сохраняются. Издержки снова вычитаются из валового PnL.

## Автоматические проверки

Все тесты находятся в `tests`. Команды выполняются **из корня проекта** с установленными зависимостями просмотрщика и тестера стратегии:

```powershell
# Все проверки: конвертер, график, стратегия и отчёты
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v

# Только конвертер: достаточно стандартной библиотеки Python
python -m unittest -v tests.test_delta_bars

# Только просмотрщик
.\.venv\Scripts\python.exe -m unittest -v tests.test_chart_data tests.test_chart_gui

# Только Supertrend: расчёты, предыстория и окно
.\.venv\Scripts\python.exe -m unittest -v tests.test_chart_supertrend

# Только расчёт сделок
.\.venv\Scripts\python.exe -m unittest -v tests.test_duration_engine
```

В VS Code тесты доступны на панели **Testing**: настройки в `.vscode/settings.json` включают unittest и поиск в `tests`. Проверки создают собственные временные файлы и базы; графические проверки работают в режиме offscreen.
